| common/idempotent/Idempotent | 注解：bizType 必填，与审批中心共用词表 |

| idempotent/IdempotentTest | 6 条验证（见下） |

**机制要点（占坑式）**：业务执行**前**先插占位记录（result_summary 留空），靠唯一键 uk_idem_key 保证并发双击只有一个请求进业务，撞键方转 1005——保证业务方法绝对只执行一次；业务成功回填摘要（"code=0,message=ok,data=..."，截断 500），业务失败删占位放行重试。同 key 未过期一律 1005（K3 拍板：拦截而非回放，表里只存摘要回放不了）；过期 key 查到即删、视为新请求可复用；同键不同参只打日志告警（request_hash 存档备查，拦截行为只看 key）。缺 X-Idempotency-Key 头返回 1001。

**刻意不用 MyBatis-Plus**：idempotent_record 无 deleted/updated_at 基座字段，不走 BaseEntity，直接 JdbcTemplate——论坛服务引同一 jar 即用，不需各自配 mapper 扫描（JdbcTemplate/DuplicateKeyException 由 mybatis-plus starter 传递的 starter-jdbc 提供，common 无需新增依赖）。

**依赖新增**：spring-boot-starter-aop（common provided / management compile）——Step 6 审计切面同用。配置新增 vio.idempotent.expire-hours=24。

**验证**：IdempotentTest 6/6——①同 key 二次 1005 且业务执行次数只 +1（新 key 才 +1）+ 落库摘要/发起人字段完整 ②缺头 1001 ③同键不同参仍 1005 ④业务失败 1006 后同 key 重试成功（占位已释放）⑤expire_at 改到过去后同 key 视为新请求（方案验证栏"过期后 key 可复用"）⑥未登录 401+1002。全量回归 37/37（Auth 16 + Idempotent 6 + DataScope 5 + ErrorHandling 7 + Mybatis 3）。

**已知项**：并发竞态路径（两请求同时插占位）由唯一键兜底，单线程测试覆盖不到，代码路径已写并注释；无全局过期清理定时任务（按需清理量小，学期规模约万级行，idx_idem_expire 已预留——如后续要加再补）。
