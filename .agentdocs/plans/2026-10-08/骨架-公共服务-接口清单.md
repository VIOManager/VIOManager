## 0. 为什么现在出这份清单

规范铁律 2 是接口先行：先定义接口，负责人确认，前后端才并行开工。骨架是全组的前置依赖，A/B/C 三线清单已入库，唯独骨架域缺一份——本文件补齐，开发会话对着接口定义写代码，不对着方案散文自由发挥。

## 1. 错误码表（骨架维护三段）

1xxx 通用段 1001–1007 见规范 §4，任何人不得占用。2xxx / 6xxx 由骨架定义：

| code | 含义 |
|------|------|
| 2001 | 登录名或密码错误 |
| 2002 | 账号已停用 |
| 2003 | 登录名已存在 |
| 2004 | 原密码不正确 |
| 6001 | 审批单不存在或已处理 |
| 6002 | 无权处理该审批 |
| 6003 | 当前审批状态不允许该操作 |

建议扩展 1xxx 通用段（文件公共服务的校验码，归组长维护）：

| code | 含义 |
|------|------|
| 1008 | 文件格式不允许 |
| 1009 | 文件超过大小上限 |
| 1010 | 文件检出病毒，已拒绝 |
| 1011 | 病毒检测服务不可用 |

1008–1011 与 C 线 5001/5002 的分工（待确认）：骨架文件接口做通用格式黑白名单与全局大小限制，用 1xxx；C 线在材料提交时按 requirement 的 allowedFormats/maxSizeMb 做业务校验，用 5xxx。两层都校验，各用各的码。

## 3. 认证与账号（/api/auth）

机制：JWT 载荷 `userId role orgId realName pwdUpdatedAt`，时效 2 小时（论坛阶段2 只验签不查库）；请求带 `Authorization: Bearer <token>`。

| 编号 | 接口 | 说明 |
|------|------|------|
| A01 | POST /api/auth/login | body：loginName password。成功 data：token userId realName role orgId defaultPassword（是否仍为初始密码，前端据此弹改密提示）。失败 2001/2002；成功失败均记 sys_login_log。不要求幂等头 |
| A02 | PUT /api/auth/password | 本人改密。body：oldPassword newPassword。原密码错 2004；成功后 defaultPassword 归 0、pwd_updated_at 更新，旧 token 全部失效 |

账号管理（绑定账号、改登录名、重置密码）按 K4 结论：骨架只提供进程内 AccountService，HTTP 面由 A 线 M13 出——本清单不含 /api/users 端点。

## 4. 字典（/api/dicts）

| 编号 | 接口 | 说明 |
|------|------|------|
| D01 | GET /api/dicts/{code} | 通用字典读。data：字典项数组 itemValue itemLabel source auditStatus sortNo。登录即可调，前端枚举下拉统一走它 |

## 5. 文件服务（/api/files）

| 编号 | 接口 | 说明 |
|------|------|------|
| F01 | POST /api/files | multipart：file bizType bizId（可空）。通用格式黑白名单与全局大小限制（1008/1009）；MinIO 落盘后 ClamAV 扫描：CLEAN 放行、INFECTED 拒绝并审计（1010）。**扫描服务不可用时放行并标记 UNAVAILABLE（组长 2026-10-10 拍板：不因服务故障影响用户，error 日志留痕）**。成功 data：fileId scanStatus originalName。带 X-Idempotency-Key 防重复上传 |
| F02 | GET /api/files/{id}/download | 鉴权流式下载，不暴露对象地址。1004 不存在 / 1003 无权限；每次下载写审计日志（操作人、时间、IP）并累加 download_count |

## 6. 审批中心（/api/approvals）

三视角查询：view=TODO 我的待办（管理员）/ MINE 我发起的 / TARGET 我是目标人。列表项：id bizType bizTitle status applicantName targetMemberName applyReason handleComment handledAt createdAt。数据范围：超管全部、部门管理员本部门、学生仅自己发起或作为目标人。

| 编号 | 接口 | 说明 |
|------|------|------|
| P01 | GET /api/approvals | 参数 view status bizType page size，分页格式按规范 §2.3 |
| P02 | POST /api/approvals/{id}/approve | 管理员批准，body：comment。事务内按 bizType 路由 ApprovalHandler 回调，同一审批单至多回调一次（骨架条件更新保证）。6001/6002/6003 |
| P03 | POST /api/approvals/{id}/reject | 管理员驳回，body：comment。回调 onRejected（各线通常无动作） |
| P04 | POST /api/approvals/{id}/cancel | 发起人在 PENDING 状态可取消。6002/6003 |
| P05 | POST /api/approvals/{id}/agree | 目标人同意（如被邀请队员），body：comment |
| P06 | POST /api/approvals/{id}/refuse | 目标人拒绝 |
| P07 | PUT /api/approvals/read | 已读标记。body：ids 数组 + asRole（APPLICANT/TARGET/APPROVER），只置当前视角的已读位 |
| P08 | GET /api/approvals/unread-count | 两类未读数：todoCount（待处理邀请与解散通知）+ resultCount（我的申请被处理的结果） |
| P09 | GET /api/approvals/{id} | 详情含 approval_record 操作流水（动作、操作人、意见、时间）。本清单新增项：PRD §3.9 要求展示处理意见与时间，详情带流水最省事 |

P02–P06 均带 X-Idempotency-Key；每个动作写 approval_record 流水；过期任务由定时任务扫 expire_at 转 EXPIRED，不提供 HTTP 过期接口。

## 7. 进程内契约（非 HTTP，B/C/A 线直接调）

| 契约 | 签名要点 | 使用方 |
|------|----------|--------|
| ApprovalClient.createApproval | bizType bizId bizTitle payload快照 applicant target approverOrg → approvalId | B 线 TE03/04/07/09、C 线 A03、A 线 S05 |
| ApprovalHandler SPI | onApproved（approvalId bizId payload，返回新建业务 ID 供骨架回填 approval.biz_id）/ onRejected（approvalId bizId payload），实现注册为 Bean，按 bizType 路由，事务内执行；同一审批单至多一次由骨架保证，事务外副作用实现方按 approvalId 自防 | B 线（建队/加人/移除/指导教师）、C 线（成果生效联动）、A 线（学期切换执行） |
| AccountService | bindAccount（默认登录名=学工号，初始密码 abc123）/ changeLoginName / resetPassword（defaultPassword 回 1） | A 线 M13 |
