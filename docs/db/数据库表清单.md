## 备注与观察

1. **命名规律**：业务域前缀清晰——`sys_`（平台）、`member`（人员）、`contest`（比赛）、`team`（赛队）、`material`（材料）、`achievement`（成果）、`project`（项目）、`schedule` / `course` / `timetable` / `class`（排班课表）、`performance_`（绩效）、`kb_`（知识库）、`ai_`（AI 助手）、`approval`（审批）。技术交流原 `tech_` 前缀表已迁论坛库 vioforum（`forum_` 前缀）。
2. **演示数据覆盖**：14 张表有数据，集中在骨架链路（账号 / 组织 / 字典 / 学期）、审批中心（7 单 + 10 流水，对应"可测评"要求）、B 线局部（比赛 / 赛队 / 成果各 1-3 条）与 A 线人员（5 人）。其余 38 张为空——这些模块的页面演示目前依赖前端 mock 层（`front/src/api/mock/`）。
3. `sys_login_log` 的 2 条记录是 2026-10-14 联调验证登录产生（1 次失败 + 1 次成功），非演示数据。
4. **改表铁律**：`V1__init_52_tables.sql` 禁改（Flyway 校验哈希，改了启动报错）；已应用的 `V2__remove_forum_domain.sql` 同样禁改。表结构变更只允许新增 `V3__xxx.sql` 并同步 `docs/db/initsql.sql`，经组长批准。
