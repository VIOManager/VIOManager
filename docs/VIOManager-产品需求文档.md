# VIOManager 产品需求文档

> 项目名称：**VIOManager**（黑龙江科技大学科创团队协作管理平台）
> 编写日期：2026-09-22（融合修订版）
> 融合来源：VIOManager 原始 PRD + 泓海管理平台制作需求
> 修订要点：三端架构（超级管理员端 / 部门管理员端 / 普通学生端）；组织下分子组织，分子组织内各自排班；保留学期作为顶层维度；队长可直接查看队友信息（沿用 VIOManager 既有策略）；新增技术交流与绩效周报模块；本地优先 AI + OpenAI 兼容可切换

---

## 1. 项目概述

VIOManager 是一套面向**黑龙江科技大学科创团队**（规模 100–200 人）的协作管理平台，以"**学期**"为生命周期，覆盖成员档案、比赛/项目、技术交流、绩效统计、排班调度、AI 助手等全流程。系统既保留 VIOManager 原有的精细化赛事管控能力（比赛→组队→材料→成果），又融入了泓海平台"团队协作 + 绩效驱动 + 知识沉淀"的运营诉求。

**解决的核心问题**：

- 比赛和赛队信息散落在微信群/Excel → 统一平台按学期归档
- 材料收集靠人工催 → 配置要求自动统计齐全率
- 获奖记录毕业即丢失 → 成果档案化可导出
- 排班靠人工 → 课表导入自动算空课，分子组织各自排班
- 查信息要翻表 → AI 自然语言查询
- 团队周工作成果无量化 → 周工作上报+打分+活跃度提示
- 技术学习资源分散 → 平台每日推送电控/建模/AI 内容并沉淀知识库
- 项目文件无规范 → 统一项目文件管理 + 病毒检测

**当前不做**：多组织隔离（仅服务单一科创团队）、复杂多级审批（仅两层）、AI 写操作、历史快照、自动排班、通知中心（仅审批红点）、BI 看板。

**部署**：先以简单服务器部署测试，后续可扩容；数据库由初始超级管理员提供，后续由用户和管理员上传增新；AI 优先本地部署（Ollama 等），同时支持任意 OpenAI 兼容 LLM 切换。

## 2. 角色与权限

系统分**三端**：**超级管理员端**、**部门管理员端**、**普通学生用户端**。

> 设计原则：**部门管理员是超级管理员的子集**——超级管理员拥有全部管理能力 + 独占项（学期切换、系统配置、跨部门数据、权限调整）；部门管理员仅可见/操作本部门（子组织）数据；学生只看自己参与的数据。

### 2.1 三端角色

| 端 | 角色 | 典型用户 | 权限范围 |
|----|------|---------|---------|
| 超级管理员端 | 超级管理员 | 平台总管理员（1 人） | 全平台所有数据 + 学期切换 + 系统配置 + 权限调整 + 跨部门操作 |
| 部门管理员端 | 部门管理员 | 各子组织负责人（每个小组织一个） | 本部门（子组织）内的人员/赛队/项目/绩效/排班 + 本部门内审批 |
| 普通学生端 | 学生用户 | 团队成员 | 仅自己参与的赛队/项目/排班/材料/成果 |

### 2.2 业务角色补充

- **赛队内角色**：队长、队员、指导教师（教师类型人员可被邀请挂名到赛队/项目/比赛）
  - **队长**：发起组队/加人/项目申请、提交材料和成果、查看本队成员完整信息（沿用 VIOManager 既有策略，**无需申请**）
  - **队员**：仅查看"本人信息"和"队伍公开信息"（队名/项目名/比赛名/赛队状态等），**不可查看队内任何其他成员的个人信息字段**；可确认/拒绝入队、退出队伍
  - **指导教师**：查询权限不低于队长，**默认只读**；不参与队伍投票和队长变更；可被邀请/移除
- 一个赛队只能有一个队长；指导教师可有多个（依模板规则约束）

### 2.3 权限规则

- 超级管理员看全平台；部门管理员看本部门；普通学生只看自己参与的
- 没有直接执行权限的动作不直接拒绝，可转为"发起申请"走审批
- 所有审批留痕（审批人、申请人、时间、备注）
- 队伍权限以"在队且未退出"为准，退出/被移除后立即失去队伍相关权限
- AI 助手权限严格等于当前登录用户

**人员信息字段可见范围**（完整字段：学院、专业、班级、姓名、性别、民族、学号、手机号、身份证号、邮箱、证件照、电子签名 + 技能标签）：

| 信息项 | 超级管理员 | 部门管理员(本部门) | 队长(本队) | 队员(本队) | 普通学生 | 本人 |
|--------|-----------|-------------------|-----------|-----------|---------|------|
| 姓名 | ✓ | ✓ | ✓ | ✗ | ✓ | ✓ |
| 学院 / 专业 / 班级 | ✓ | ✓ | ✓ | ✗ | ✓ | ✓ |
| 手机号 | ✓ | ✓ | ✓ | ✗ | ✓ | ✓ |
| 学号 / 学工号 | ✓ | ✓ | ✓ | ✗ | ✓ | ✓ |
| 邮箱 | ✓ | ✓ | ✓ | ✗ | ✗ | ✓ |
| 性别 / 民族 / 电子签名 | ✓ | ✓ | ✓ | ✗ | ✗ | ✓ |
| 身份证号 | ✓ | ✓ | ✓（限本队，支持下载） | ✗ | ✗ | ✓ |
| 证件照 | ✓ | ✓ | ✓（限本队，支持下载） | ✗ | ✗ | ✓ |
| 技能标签 | ✓ | ✓ | ✓ | ✗ | ✓ | ✓ |
| 登录名 | ✓ | ✗ | ✗ | ✗ | ✗ | ✓ |

> **队员列规则：队员仅可查看"本人"以及"队伍公开信息"（队名/项目名/比赛名/赛队状态等），不可查看队内任何其他成员的个人信息字段。** 队长查看队友信息无需走申请（沿用 VIOManager 既有策略）。身份证号与证件照对超级管理员、部门管理员、队长（限本队）、本人完全可见并支持下载；下载链路需鉴权（日志记录操作人/时间/IP）。

## 3. 功能需求

### 3.1 认证与账号

- 用户通过登录名+密码登录。新绑定的账号默认密码为 `abc123`，首次用默认密码登录时每次弹出安全提示引导改密。
- 所有角色可在右上角修改密码，改后强制重新登录。登录态过期自动跳转登录页。
- 超级管理员或部门管理员可为人员绑定登录账号（默认登录名=学工号），已绑定的可修改登录名或重置密码。

### 3.2 人员档案

> 字段全集（融合泓海）：姓名、学院、专业、班级、性别、民族、学号、学工号、手机号、身份证号、邮箱、证件照、电子签名、技能标签、所属组织、类型（学生/教师/其他）。

- **录入方式**：管理员可手工新建或 Excel 批量导入。学号（学工号）可空、不可重复、不可修改。
- **导入行为**：学号已存在的行跳过，返回成功/失败数和每行错误原因。
- **Excel 导入模板（共 13 列）**：姓名（必填）、学号/学工号、手机号、学院、专业、班级、性别、民族、身份证号、邮箱、证件照、电子签名、所属组织、类型（必填，学生/教师/其他）。
  - **文本类字段**（姓名/学号/手机号/学院/专业/班级/性别/民族/身份证号/邮箱/所属组织/类型）→ 直接入库 MySQL。
  - **图片类字段**（证件照、电子签名）→ 模板保留列名占位（留空不报错）；导入后在档案详情页另行上传至 **MinIO** 对象存储，系统回填存储路径到 MySQL 关联字段。
- **人员列表**：支持按关键词（姓名/学号/手机号模糊）、组织、类型、技能标签筛选，显示账号绑定状态。
- **人员详情**：展示全部字段；证件照与电子签名支持上传/更新（覆盖式，单图）；技能标签可多选，支持自定义补充（管理员维护技能字典 + 用户自行补充并存）。
- **技能标签**（泓海融入，预设字典）：python、CAD、AIGC、视频剪辑、机械设计、其他。用户可补充新技能，提交后由管理员审核入库。
- **删除规则**：管理员可删除人员，但只移除账号与角色，业务记录（材料/佐证/成果）保留；队长身份禁止删除（需先解散队伍）；不能删除当前登录账号；普通队员删除时清除其队伍成员关系。
- **班级标准导出**：由内置学院-专业-简称映射纯静态生成（13 学院 39 专业），不依赖数据库或外部文件。前端各页面学院下拉统一从后端获取。
- **隐私保护**：身份证号、证件照加密存储；任何接口返回前按 §2.3 权限表裁剪；下载操作写入审计日志（操作人/时间/IP/对象）；不在列表页/搜索结果中直接展示，需进入详情才可见。
- **成员等级体系扩展性**（泓海融入）：当前体系为 学生用户 → 部门管理员 → 超级管理员；后续可扩展"部门管理员权限下发至用户"（即允许某些用户代理部门管理员部分职责），具体下放规则后续迭代。

### 3.3 组织管理

- 组织以**树形结构**管理，类型含学院/部门/班级/社团部门/其他。
- 支持创建/编辑/删除，选择上级组织时自动排除自身及子孙防循环引用。有子组织时禁止删除，删除后该组织下人员所属组织置空。
- **泓海特色：组织下分子组织**——鸿海作为顶层组织，下面按"**工作性质/工作区域**"划分多个子组织（如**数媒协会、数媒二楼**、XX 工作室、XX 楼层团队等），子组织之间**工作职责不同**。每个子组织作为独立节点存在，子组织内独立排班、独立管理本组人员/项目/绩效。
- 人员关联组织：列表显示所属组织、可按组织筛选、新建/编辑可选、详情显示。Excel 导入时按组织名称匹配，不存在/不唯一时该行报错。

### 3.4 学期管理

- 学期是组织一切业务数据的维度。仅**超级管理员**可创建/编辑/删除学期。创建时名称不可重复。有关联比赛/队伍/成果/切换任务的学期禁止删除。
- **学期切换流程**：超级管理员发起切换 → 输入超级管理员密码二次确认 → 创建切换任务，进入 30 分钟待执行窗口 → 执行前可取消 → 执行时系统进入维护锁定，全员禁止访问 → 旧学期归档、新学期激活 → 未结束的比赛、赛队和成员关系自动继承到新学期。切换任务使用乐观锁防止并发执行。

### 3.5 比赛管理

**模板与规则**：预设比赛模板含规则配置（人数限制、重复参赛规则、指导教师数、跨赛道/跨队限制等）。规则三级继承：模板默认 → 比赛实例覆盖 → 赛道级覆盖。规则在前端展示为中文标签，布尔值显示"是/否"，赛道无覆盖时显示"跟随比赛规则"。模板被比赛引用时禁止删除。

**比赛实例**：关联学期创建，配置报名/比赛时间、联系人、描述。可为比赛添加多个赛道，每个赛道可覆盖比赛级规则。比赛列表显示学期名、状态、报名/比赛起止时间。

**状态流转**：草稿 → 已发布 → 报名中 → 进行中 → 已结束 → 已归档。按序流转不可跳转。发布前检查：基础信息、规则已配置；需要赛道时已配赛道；需要材料时已配材料要求。学期切换时已结束比赛自动归档。

**泓海融入：自动收集比赛信息**——管理员可登记外部比赛来源（爬虫接口/RSS/手工），系统按比赛时间节点自动归集至"待处理比赛池"，再由管理员确认为正式比赛实例。组队规则沿用 VIOManager：比赛若为 5 人一组则用户填前 2 名+剩 3 名由管理员分配；若为 3 人一组则填前 2 名+剩 1 名由管理员分配；剩余位置由**本部门管理员**统一分配。

### 3.6 赛队管理

**组队流程**：学生在比赛报名中状态下发起组队申请（选比赛+赛道，填队名和项目名） → 系统校验比赛状态、队名唯一性、同比赛加队限制、跨队队长限制 → 生成待审批申请 → **本部门管理员**审批 → 通过后创建正式赛队，发起人自动成为队长。

**加人流程**：队长发起加人申请 → 按姓名模糊搜索选人（防抖 300ms，已在队成员置灰） → 系统校验人数上限、重复参赛限制、目标人身份、同队已有待审批申请 → 部门管理员审批 → 审批时以最新成员关系复核（封堵两队同时邀请同一人的时序漏洞） → 通过后成员状态为"未确认" → 队员本人确认/拒绝入队。

**加指导教师流程**：队长发起加指导教师申请 → 搜索仅显示"教师"类型人员 → 部门管理员审批 → 通过后正式生效（指导教师默认只读；查询权限≥队长）。

**成员状态展示**：已确认（绿）/ 未确认（橙）/ 已拒绝（红）/ 未审批。普通队员未确认但有效，指导教师审批通过即生效。

**成员管理**：管理端或队长可移除成员（队长不可删自己，软删保留历史）。非队长可主动退出队伍，队长收到通知（审批中心红点）。队长或管理端可解散队伍，但有材料/成果/待审批申请时拒绝，解散后成员收到通知。

**防重复申请**：同比赛+同队名有待审批申请、同队伍+同目标有待审批申请、目标已在队——均直接拒绝。

**数据可见性**：超级管理员看全部赛队；部门管理员看本部门赛队；普通学生只看自己所属队伍。**队长与指导教师可直接查看队友信息无需申请**（字段范围按 §2.3 表裁剪）；**队员仅可看"自己"和"队伍公开信息"，不能看队友任何个人信息**。非本队成员不可查看赛队详情和成员名单（封堵按 ID 枚举越权）。已退出/被移除的成员立即失去材料上传、成果提交、队伍查看等全部权限。

### 3.7 材料管理

- 管理员为比赛配置材料收集任务，添加多条材料要求。每条要求含类型（12 种预设：报名表、项目书、承诺书、身份证复印件、学生证复印件、团队合照、答辩 PPT、研究报告、源代码、获奖证书、佐证材料、其他）、是否必传、允许格式、命名规则（可选）。
- **材料提交流程**：队长在赛队详情页逐项上传材料或上传压缩包 → 必须在队成员才能上传，材料要求须与赛队所属比赛匹配 → 同一要求可重新上传覆盖 → 系统自动统计齐全率 → 必交项未齐队伍状态变"材料待补"，齐全后变"材料已交"。
- 有审批通过成果但未传佐证材料的队伍，必交项额外加 1"成果佐证材料"（待审批成果不提前占用）。
- 管理端查看提交概览和打点详情，已交文件可预览和下载，可打包下载队伍全部材料（非管理用户须本队成员）。
- 材料要求已有提交记录时禁止删除，材料任务下任一要求有提交记录时禁止删除。

### 3.8 成果管理

**录入流程**：队长提交成果（类型/名称/级别/时间/描述+佐证材料） → 管理员提交直接生效，队长提交待审批 → 管理员审批通过/驳回 → 通过后成果生效并计入材料统计。

成果类型含获奖/评级/资质/活动成果/其他。佐证材料为单文件覆盖式上传（不限于奖状，论文、专利、作品均可），仅限当前队长上传（退队前队长不可上传）。

成果列表仅管理角色可见全量。普通用户通过赛队成果和个人视角查询。管理员可编辑成果（名称/级别/日期/描述）和删除（级联清理）。

个人贡献从赛队成员关系和赛队成果动态聚合（参赛记录+获奖记录），不单独维护冗余表。获奖导出仅本人或管理员可操作，且只导出审批通过的成果。

### 3.9 审批中心

- 超级管理员看全部审批；部门管理员看本部门审批；普通用户只看自己发起的或自己作为目标人的。
- 操作按角色区分：发起人可"取消"，目标人可"同意/拒绝"，管理员可"批准/拒绝"。
- 列表显示审批意见和处理时间。
- 菜单红点提示两类未读：① 待处理邀请和队伍解散通知 ② 发起人的申请被管理员处理的结果。进入审批中心后标记已读，下次不再提示（已读状态持久化）。
- 当前需审批的动作：创建赛队、添加/移除队员、录入成果、学期切换。

### 3.10 项目管理（泓海融入 + 独立于赛队）

> **关键定位**：项目是**独立于赛队**的业务实体。**项目所有人（负责人）≠ 拿这个项目去打比赛的人**——例如某学生拥有 Python 工具项目，可挂到不同赛队/不同赛道下由其他同学拿去参赛。
> 项目可挂载比赛（可选），项目下可挂指导教师（挂名，不参与赛队权限）。

- **项目字段**：项目名称、项目描述、项目所有人（学工号）、所属比赛/赛道（可选挂载）、项目指导教师（可选挂名）、项目成员（参与开发但非所有人）、所属学期、所属子组织、比赛时间节点、任务列表、项目文件。
- **归属关系**：
  - 项目**归个人**（项目所有人）：项目所有人对本项目拥有完整管理权。
  - 比赛**归赛队**：拿项目参赛的是赛队，赛队与项目通过"挂载关系"关联，**一个项目可被多个赛队挂载**。
- **可见性规则**（与赛队解耦）：
  - 项目所有人：可看/可改/可删本项目。
  - 项目成员：可看本项目，不可改。
  - 项目指导教师：可看本项目（只读），不可改。
  - **本部门其他用户**：仅可查看部门管理员审批通过的、且自己作为项目成员的项目；其他需用户提交"项目查看申请" → 本部门管理员审批 → 审批通过后获得查看权限（一次性或限时）。
  - **跨部门用户**：不可查看，除非对方部门管理员审批通过。
  - **超级管理员**：可看本部门所有项目。
- **任务列表**：以"比赛时间节点"为锚点（节点类型：比赛报名开始、比赛报名截止、作品提交、其他可扩展），每个任务记录"是否完成"。
- **比赛时间节点**：由部门管理员维护并审核，审核通过后自动同步给已挂载该比赛的项目。
- **项目文件上传**：支持各类型文件，**强制病毒检测**，命中病毒则禁止上传并记录审计日志；图片类入 MinIO，其他入 MySQL 关联表。
- **关联赛队**：项目可被 0..N 个赛队挂载，挂载时选择赛道；赛队详情页展示"本队挂载的项目"；项目详情页展示"使用本项目的赛队"。

### 3.11 排班管理（VIOManager + 泓海"分子组织排班"）

**课表导入流程**：管理员下载导入模板（16 列+5 条示例行，格式对齐学校导出） → 填写上传 → 学期名称自动归一化关联学期 → 系统生成课表班级↔人员档案班级的映射列表 → 管理员批量确认映射 → 未确认映射的班级不参与空课统计。

**空课查询**：按学期+周次输出 7×5 时段空课名单，含班级信息，按年级分组展示（学号推导优先，班级名兜底）。仅超级管理员和部门管理员可用。

**子组织排班（泓海特色）**：每个子组织（如数媒协会、数媒二楼）独立排班——排班按"**学期+周次+子组织**"三维分配班次。**同一周次同一人在同一子组织内不可分配到多个班次；跨子组织不互通排班**（排班只在所属子组织内进行，跨子组织成员身份不影响排班）。可导出周排班表和学期排班统计。

**我的排班**：普通用户侧边栏有"我的排班"，查看自己被排到的班次（学期/周次/子组织/星期/节次），管理端隐藏此项。

### 3.12 技术交流（泓海融入）

- 平台每日自动推送技术内容，分类覆盖：电控、建模、AI、视频剪辑等（可扩展）。
- 内容形态：视频、文章、教程链接等。
- 推送来源：管理员手工录入、外部 RSS/公众号链接、AI 自动生成（基于本地 LLM 摘要外部公开内容）。
- 用户可在"技术交流"模块查看历史推送、收藏、按标签筛选；管理员可置顶/撤回推送。
- 本期不要求严格个性化推荐，按订阅标签展示即可。

### 3.13 绩效统计（泓海融入）

- 用户上传本周工作内容到平台（文字+可选附件）；
- 部门管理员或超级管理员对本周工作进行审核打分；
- **按子组织分组计算**：不同子组织的绩效计算方式/权重不同（例如数媒协会与数媒二楼各有独立打分维度），绩效数据按"子组织"维度隔离统计；
- 系统自动统计每一周的绩效分数，并给出**活跃度 / 功劳程度提示**（如"近 4 周活跃度上升""功劳度高"等标签化反馈）；
- 绩效数据按学期+周次+子组织三维归档，可按人/按子组织聚合导出；
- 绩效分数可作为评优、岗位调整的参考依据。

### 3.14 知识库（泓海融入）

- 内置知识库分类：Python 教程、机械设计规范、各类型三维建模教程、AI 提示词库、其他（可扩展）。
- 用户可浏览/收藏/评论；管理员可发布/编辑/置顶/删除。
- AI 提示词库与 AI 助手联动，用户可在聊天界面一键复用提示词。
- 知识库内容来源：管理员上传、外部链接收录、AI 总结（基于本地 LLM 离线生成）。

### 3.15 AI 智能助手

> 前端入口默认停用（代码保留可随时恢复），后端服务正常运行。

- **本地优先 + OpenAI 兼容可切换**：默认使用本地部署的 LLM（如 Ollama + Qwen/Llama-Chinese 等），同时支持切换任意 OpenAI 兼容 LLM（DeepSeek、通义千问、OpenAI 等）。部署侧不强制外网。
- ChatGPT 风格聊天界面，流式输出。AI 通过 Function Calling 自动调用后端查询能力，获取数据后组织回答。
- 可查询：人员档案、个人贡献（参赛+获奖）、赛队详情、未交材料赛队、赛队成果、空课信息、我的排班、本周绩效。空课查询仅管理角色可用。
- 查询结果按当前用户权限裁剪。支持多对话管理。
- AI 回复异常中断时提示"回复可能不完整"。
- 须通过 JWT 验签才能调用，工具调用时转发用户令牌给后端做权限过滤。
- 本期不允许 AI 执行写操作、审批、直接访问数据库。

### 3.16 概览统计

- **超级管理员端**：登录后看全局指标（人员总数、本学期比赛、活跃赛队、待审批、跨部门概览）。
- **部门管理员端**：本部门指标（本部门人员、本部门比赛、本部门赛队、本部门待审批、本部门绩效）。
- **普通学生端**：个人指标（我的队伍、我的成果、待办、材料状态、本周绩效）。
- 界面为 HUD 风格。

### 3.17 审计日志

- 所有关键操作（含 AI 查询）记录审计日志：操作人、IP、业务类型、摘要、成功/失败。异步写入不阻塞业务。
- 超级管理员可按关键词、时间范围、操作类型筛选查看全平台日志；部门管理员仅可查看本部门日志。

## 4. 前端交互规范

**菜单可见性**：

- 超级管理员端：显示全部管理模块（含"学期切换"独占项）
- 部门管理员端：仅显示本部门相关模块，隐藏"学期切换""系统配置""权限调整"
- 普通学生端：仅显示自己有权限的模块，隐藏管理模块；显示"我的排班"，隐藏"管理员菜单"；隐藏管理员菜单中的"我的成果"

**三端页面统一入口**：登录后根据角色自动路由到对应端首页。技术交流、知识库、审批中心在三个端都有入口但权限/数据范围不同。

**表单提交**：全站防重复提交（提交中禁用按钮），断网重连后不会重放。列表快速切换筛选时丢弃过期响应不串数据。模糊搜索防抖 300ms。

**时间显示**：统一 `YYYY-MM-DD HH:mm:ss` 格式。

**异常处理**：断网恢复后提示手动刷新。AI 回复中断提示"回复可能不完整"。登录态过期自动跳转登录页。

**确认操作**：删除/解散等高风险操作需二次确认弹窗。

## 5. 非功能需求

**安全**：

- 密码 BCrypt 加密
- JWT 密钥必填不使用公开默认值
- AI 助手须验签
- 文件下载经鉴权不暴露存储地址
- 所有越权场景已封堵（打包下载、队伍信息、登录名、成果列表/导出、佐证上传、跨部门数据访问等）
- 上线前必须修改 admin 默认密码
- 项目文件上传强制病毒检测，命中病毒则禁止上传并记录审计

**性能**：

- 列表查询避免 N+1 批量组装
- 文件下载流式传输不占内存
- 前端页面懒加载首屏只加载当前路由
- 审计日志异步写入
- gzip 三层压缩（SSE 不受影响）

**部署**：

- 先以简单服务器（如单机 Linux + Docker）部署测试
- 后续可扩容到大容量服务器；数据库由初始超级管理员提供，后续由用户/管理员上传增新
- Docker Compose 启动 6 容器；支持 1Panel 导入；对外端口默认 8088
- 所有配置通过环境变量管理
- AI 优先本地部署（Ollama 等），无需外网；同时保留 OpenAI 兼容 LLM 配置位
- 演示数据含 5 个角色账号、1 个组织/学期/比赛模板/比赛/2 个赛队/1 条获奖记录

**可扩展性**：

- 后续扩展方向主要为增添新模块（用户反馈驱动）以及补充现有模块，方便后续系统维护与迭代

## 6. 融合变更记录（修订版 vs VIOManager 原始版）

| 项 | VIOManager 原始版 | 融合修订版（VIOManager 泓海版） | 变更原因 |
|------|--------|--------|--------|
| 端结构 | 管理端 + 用户端 | **超级管理员端 + 部门管理员端 + 普通学生端** | 泓海场景需区分"平台总管理员"与"各部门小管理员" |
| 角色体系 | 4 层（超管/组织负责人/部门负责人/师生） | **3 端**：超管 + 部门管理员 + 学生 | 泓海只需 3 层，部门管理员是超管子集 |
| 组织模型 | 学院/部门/班级/社团/其他 | **新增"分子组织"概念**：按工作性质/工作区域划分子组织（如数媒协会、数媒二楼、XX 工作室），各子组织独立排班/独立运营 | 泓海强调子组织之间"工作不一样" |
| 个人信息查看 | 队长可看本队，管理员可看全部 | **沿用，删除泓海"申请查看"机制** | VIOManager 既有策略已满足需求，简化流程 |
| 比赛组队 | 标准报名流程 | **保留**：5 人队填前 2、3 人队填前 1、剩余由本部门管理员分配 | 泓海原需求 |
| 学期管理 | 完整保留 | **完整保留**（顶层维度） | 融合决策 |
| 排课排班 | 仅按学期+周次 | **新增分子组织维度**：学期+周次+子组织 | 泓海特色 |
| 新增模块 | — | **项目管理 / 技术交流 / 绩效统计 / 知识库** | 泓海原文档独有 |
| AI 助手 | 任意 OpenAI 兼容 LLM | **本地优先 + OpenAI 兼容可切换** | 泓海强调本地部署 |
| 部署 | Docker Compose 6 容器 | **保留 + 强调"先简单服务器测试，AI 本地优先"** | 泓海原文档 |
| 项目文件 | 无独立模块 | **新增项目管理模块 + 强制病毒检测** | 泓海原文档 |
| 人员档案字段 | 7 列导入模板（无证件照/身份证号/民族/邮箱） | **升级到 13 列**：补齐泓海独有字段（证件照、身份证号、民族、邮箱）+ 技能标签 | 泓海原文档 §1 |
| 隐私字段保护 | 无明确分级 | **分级保护**：身份证号/证件照对超管/部门管理员/队长(本队)/本人可见可下载，需审计；其他弱隐私字段按上表 | 用户决策——队长也要能看能下 |
| 成员信息分发模块 | 无 | **丢弃**，与人员档案合并 | 泓海原文档独立模块，经用户决策丢弃 |
| 术语 | — | 统一用"部门管理员"，废弃泓海原"模块管理员"称谓 | 用户决策 |
| 队员隐私可见 | 队员可看本队成员姓名/院系等基础字段 | **改为**：队员仅可看"自己"+"队伍公开信息"，不能看队内任何其他成员的个人信息字段 | 用户决策——队员不需要互相看 |
| 指导教师角色 | 无（VIOManager 原含，融合初版删除） | **恢复**：指导教师作为赛队内角色 + 项目管理字段双路径存在 | 用户决策——比赛/项目挂名时需要 |
| 项目归属 | 成果归赛队 | **新增独立项目管理模块**：项目归个人（项目所有人），与赛队通过挂载关联；一个项目可被多赛队挂载 | 用户决策——项目所有人 ≠ 参赛人 |
| 排班冲突规则 | 仅同周次同人冲突 | **强化**：同周次同人仅在同一子组织内不可分配多班次；跨子组织不互通排班 | 用户决策——排班不可能跨组排 |
| 绩效计算 | 通用公式 | **按子组织分组计算**：不同子组织维度/权重不同 | 用户决策——不同组绩效计算方式不一样 |
| Excel 导入图片 | 无明确方案 | **文本入 MySQL、图片入 MinIO**：13 列全保留，图片列留空不报错，由用户在档案详情补传至 MinIO | 用户决策——统一上传再统一入库 |
| 奖金分配 | 无 | **删除**奖金分配相关字样，绩效仅作评优/岗位调整参考 | 用户决策 |
