## 通用约定（全接口一致）

1. **统一响应壳**：所有接口返回 `{ code, message, data }`；`code=0` 成功，`data` 为业务数据；非 0 时 `message` 为可直接展示的中文提示。
2. **认证**：除登录外全部需要 `Authorization: Bearer {token}`；token 无效/过期统一回 `1002`，前端会清 token 踢回登录页。
3. **幂等**：所有"上传类"和容易重复点击的写操作带请求头 `X-Idempotency-Key`（UUID，前端每次操作生成）；命中重复键回 `1005`。
4. **分页**：`page`（从 1 起）/ `size`，响应 `data` 为 `{ list, total }`（仅人员列表用到，其余列表当前数据量小、直接返回数组）。
5. **日期格式**：日期 `yyyy-MM-dd`，带时间 `yyyy-MM-dd HH:mm`，均为字符串。
6. **字段裁剪**：涉及隐私（身份证/手机号/班级等）的接口按"管理端/本人/队长视角"返回不同字段集，规则在各清单内注明，前端不传"我要全量"之类的参数——**后端按 token 自行判定视角**。

## ⚠️ 暂定项汇总（后端录入 Apifox 前必须逐条拍板）

| # | 事项 | 当前前端行为 | 需要拍板 |
|---|---|---|---|
| 1 | **prefillLimit 三人队取值**（全组最关键） | 模板默认 1，比赛可覆盖 | 3 人队到底 1 还是 2，影响组队申请表单上限 |
| 2 | PRD §3.2 导入模板列数 | 按 14 列生成（PRD 文字写 13 列但字段清单 14 项） | 以哪个为准 |
| 3 | 材料上传权限 | 在队在册成员（含队员）可传（PRD §3.7） | 是否收紧为仅队长（PRD §3.6 又写了队长提交） |
| 4 | 4004 重复参赛范围 | 已在队即拦（含待确认状态） | 待确认算不算"已参赛" |
| 5 | 认证/文件/审批三组接口 | 路径与字段为前端暂定稿 | 以骨架清单录入 Apifox 后为准，前端同步改 |
| 6 | 5xxx 材料成果错误码 | 前端自拟 | 后端可重排，改码前端只动 labels/mock 两处 |
| 7 | 导出类接口（材料打包/获奖清单） | 返回 `{note}` 提示，前端弹 toast | 真实形态：文件流 or 异步任务+通知 |
| 8 | zip 批量上传 | mock 按包名模拟匹配 | 真实解压在后端做，返回结构不变即可 |
