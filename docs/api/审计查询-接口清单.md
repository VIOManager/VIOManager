## 0. 一句话理解审计查询

骨架已经在所有关键接口上挂了自动记录（谁、什么时间、什么 IP、干了什么、成没成功），异步写进 audit_log 表——**写入侧全组共用，不用各线操心**。本模块只做一件事：给管理员一个**查账页面**——按人名、业务类型、成功失败、时间范围筛出日志列表。学生无权访问（PRD 明确仅超管与部门管理员）。

数据量说明：100–200 人规模一年约几万到几十万条，MySQL 单表（已建 5 个查询索引）无压力，本期不做归档。

## 1. 已登记的业务类型（bizType，随各线上线持续增加）

| bizType | 中文名 | 写入方 |
|---------|--------|--------|
| AUTH_PASSWORD_CHANGE | 修改密码 | 骨架（已生效） |
| FILE_UPLOAD | 文件上传 | 骨架（已生效） |
| FILE_DOWNLOAD | 文件下载 | 骨架（已生效，含敏感文件下载留痕） |
| APPROVAL_APPROVE / REJECT / CANCEL / AGREE / REFUSE | 审批五动作 | 骨架（已生效） |
| MEMBER_ID_CARD_VIEW 等 | 人员敏感信息查看 | A 线（M10，上线后登记） |
| TEAM_* / ACHIEVEMENT_* 等 | 赛队与成果动作 | B / C 线（上线后登记） |

新业务类型登记规则：各线在自己接口上挂 `@AuditLog(bizType=..., label=...)` 即自动入表，同时在 AQ02 返回值里出现——**无需到本清单登记**，此处表格仅为当前快照。

## 2. 接口明细（/api/audit-logs，仅 SUPER_ADMIN 与 DEPT_ADMIN）

| 编号 | 接口 | 说明 |
|------|------|------|
| AQ01 | GET /api/audit-logs | 分页列表。筛选：keyword（姓名/登录名/摘要模糊）、bizType、success（1 成功 0 失败）、startTime、endTime（时间格式按规范）。按发生时间倒序。列表项：realName loginName role bizTypeLabel summary ip success errorMessage costMillis createdAt。**request_params 列表不返回**（省流量，进详情看） |
| AQ02 | GET /api/audit-logs/biz-types | 业务类型枚举（筛选下拉用）：bizType + label 动态返回，后端加类型前端零改动 |
| AQ03 | GET /api/audit-logs/{id} | 单条详情：列表字段 + httpMethod uri userAgent requestParams。排查失败用 error_message 在列表已有 |

## 3. 数据范围

- 超级管理员：全平台全部日志
- 部门管理员：**操作人所属组织**在本部门子树内的日志（audit_log.org_id 过滤，骨架数据范围拦截器口径）
- 学生：无权访问本模块任何接口（1003）

## 4. 与骨架和其他线的对接点

- 本模块**只读** audit_log，写入侧全部由骨架 @AuditLog AOP 承担（异步、XFF 解析 IP、敏感接口 request_params 置空）
- 概览统计：无新增接口（拍板口径）——如后续要"审计异常数"卡片再议
- AI 助手（§3.15）：**不开放**审计查询给 AI 工具调用（PRD AI 可查清单无审计项）
