## 1. 认证（FS2 登录改密闭环）

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | /api/auth/login | 登录 | 匿名 |
| GET | /api/auth/me | 刷新后恢复身份 | 登录 |
| PUT | /api/auth/password | 修改密码 | 登录 |

### POST /api/auth/login

入参：`{ loginName: string, password: string }`

出参：`{ token, realName, role, defaultPassword }`，其中 role ∈ `SUPER_ADMIN / DEPT_ADMIN / STUDENT`；`defaultPassword` 1=仍用默认密码（前端弹改密引导），0=已改。

错误码：2001 账号或密码错误。

### PUT /api/auth/password

入参：`{ oldPassword, newPassword }`。**改密成功后服务端作废该用户全部旧 token**（其他端全部 1002 踢回登录），PRD §3.1。

错误码：2002 原密码不正确 / 2003 新密码与原密码相同。

## 2. 文件服务（FS4 通用上传）

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | /api/files | 上传单文件（multipart） | 登录 |

- 入参：FormData 字段 `file` + 请求头 `X-Idempotency-Key`（每次选择文件一个 UUID）
- 出参：`{ fileId, fileName, scanStatus }`，scanStatus ∈ `CLEAN / REJECTED`；病毒不通过走错误码 **1010**（不进响应体）
- 调用方（证件照/签名/材料/佐证/导入）拿到 fileId 后再调各自业务接口回填，文件服务只管存与扫

## 3. 审批中心（正式，P01–P09；前端消费视角）

契约源：后端《审批中心-接口清单》（2026-10-10，lzh 骨架域，错误码段 6xxx）。通用单据引擎：业务线进程内创建单据，管理员/目标人在中心处理，批准后按 bizType 回调业务线落地正式数据。

**状态机**：`PENDING`（唯一活动态）→ `APPROVED / REJECTED / CANCELLED / EXPIRED`（一跳终结：管理员批准与目标人同意任一先操作即终结；取消不触发业务回调）。

| 编号 | 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|---|
| P01 | GET | /api/approvals | 分页列表。参数 `view`（必填：TODO 待办 / MINE 我发起的 / TARGET 我是目标人）+ `status` `bizType` `page` `size`，创建时间倒序 | 学生调 TODO 回 1003 |
| P02 | POST | /api/approvals/:id/approve | 管理员批准，body `{comment}` | 管理员（部门管理员限审批责任组织子树内，否则 6002） |
| P03 | POST | /api/approvals/:id/reject | 管理员驳回，body `{comment}` | 同 P02 |
| P04 | POST | /api/approvals/:id/cancel | 发起人取消，body `{comment}`；**不触发业务回调** | 仅申请人本人（按人员档案 ID） |
| P05 | POST | /api/approvals/:id/agree | 目标人同意，body `{comment}`；转 APPROVED 并触发回调 | 仅目标人本人 |
| P06 | POST | /api/approvals/:id/refuse | 目标人拒绝，body `{comment}` | 仅目标人本人 |
| P07 | PUT | /api/approvals/read | 已读标记。body `{ids: string[], asRole: APPLICANT/TARGET/APPROVER}`，只置当前视角对应已读位（置位幂等） | 登录 |
| P08 | GET | /api/approvals/unread-count | 红点：`{todoCount, resultCount}` | 登录 |
| P09 | GET | /api/approvals/:id | 详情 = 列表字段 + `bizPayload` 申请快照 JSON + `records` 流水（时间正序） | 超管/发起人/目标人/审批组织子树内管理员，其余 6002 |

**幂等（规范 §6）**：P02–P06 必须带 `X-Idempotency-Key` 头（前端 `postIdem` + 每次点击 `crypto.randomUUID()`），缺键 1001、重复键 1005 不回放。

**字段**：

```
ApprovalVO        = { id, bizType, bizTitle, status, applicantName, targetMemberName,
                      applyReason, handleComment, handledAt, createdAt }   // 无已读位
ApprovalDetailVO  = ApprovalVO + { bizPayload: string, records: ApprovalRecordVO[] }
ApprovalRecordVO  = { action, operatorName, operatorRole, commentText, createdAt }
UnreadCountVO     = { todoCount, resultCount }
```

- **红点语义**：`todoCount` = 我是目标人且 PENDING 未读；`resultCount` = 我发起的已出结果未读；**管理员待办不进红点**（未绑定人员档案的纯管理账号回两个 0）。前端顶栏 chip / 菜单 badge / 页内 tab 角标均取此接口（`stores/approval.ts` 共享）。
- **行级未读点做不了**：ApprovalVO 无已读位字段，页面只能 tab 角标 + 打开详情即按视角置已读（P07）。若后续要行级红点需契约加字段（待后端确认）。
- **bizType 词表**（9 项，labels 有中文表）：`TEAM_CREATE / TEAM_ADD_MEMBER / TEAM_REMOVE_MEMBER / TEAM_ADD_ADVISOR / TEAM_DISSOLVE / ACHIEVEMENT_SUBMIT / PROJECT_VIEW / MILESTONE_APPROVE / SEMESTER_SWITCH`。
- **bizPayload**：各业务线快照 JSON 字符串，结构由各线清单登记（目前未集中登记，清单 §7 遗留）；前端只格式化展示，不解析语义。
- 错误码：6001 审批单不存在或已处理（并发批同一单后到者）/ 6002 无权处理 / 6003 非 PENDING 不允许操作；另用 1001（view 传值不合法）1003（学生调 TODO）。
- **回调联动**：批准后业务落地由后端 ApprovalHandler 回调做（如 TEAM_CREATE 批准→建队、ACHIEVEMENT_SUBMIT 批准→成果转正式态+材料任务补佐证必交项）；mock 同构模拟（`mock/approval-data.ts` 的 `registerApprovalHandler`）。业务线自审接口（成果 review）与审批中心双轨一致：自审同步终结关联审批单，审批回调也反向落地成果状态。
