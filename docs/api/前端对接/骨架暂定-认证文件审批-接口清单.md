# 骨架暂定接口清单：认证 / 文件 / 审批

作者:lzh（前端） | 创建时间:2026-10-10 14:30

## 1. 认证（FS2 登录改密闭环）

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | /api/auth/login | 登录 | 匿名 |
| GET | /api/auth/me | 刷新后恢复身份 | 登录 |
| PUT | /api/auth/password | 修改密码 | 登录 |

### POST /api/auth/login

入参：`{ loginName: string, password: string }`

出参：`{ token, realName, role, defaultPassword }`，其中 role ∈ `SUPER_ADMIN / DEPT_ADMIN / STUDENT`；`defaultPassword` 1=仍用默认密码（前端弹改密引导），0=已改。

错误码：2001 账号或密码错误。

### PUT /api/auth/password

入参：`{ oldPassword, newPassword }`。**改密成功后服务端作废该用户全部旧 token**（其他端全部 1002 踢回登录），PRD §3.1。

错误码：2002 原密码不正确 / 2003 新密码与原密码相同。

## 2. 文件服务（FS4 通用上传）

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | /api/files | 上传单文件（multipart） | 登录 |

- 入参：FormData 字段 `file` + 请求头 `X-Idempotency-Key`（每次选择文件一个 UUID）
- 出参：`{ fileId, fileName, scanStatus }`，scanStatus ∈ `CLEAN / REJECTED`；病毒不通过走错误码 **1010**（不进响应体）
- 调用方（证件照/签名/材料/佐证/导入）拿到 fileId 后再调各自业务接口回填，文件服务只管存与扫

## 3. 审批中心（⚠️ 暂定，页面 FS5 未开发，字段按顶栏待办数需要预留）

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | /api/approvals | 审批单列表（当前全量，未分页） | 登录 |
| GET | /api/approvals/pending-count | 未读待办数（顶栏红点） | 登录 |
| POST | /api/approvals/:id/read | 标记已读 | 登录 |

审批单结构（后端统一落库，各业务线只负责产生）：

```
{ id, bizType, bizId, title, detail, status, applicantName, createdAt, unread, targetMemberId? }
```

- `bizType` 已产生的种类：`TEAM_CREATE / TEAM_ADD_MEMBER / TEAM_REMOVE_MEMBER / TEAM_ADD_ADVISOR / ACHIEVEMENT_SUBMIT`（后续排班/项目等沿用此模式）
- `status` ∈ `PENDING / APPROVED / REJECTED / CANCELLED`
- `targetMemberId`：需要**指定成员处理**的单子（如队员入队确认）填成员 id，空=管理员处理
- 业务侧审批通过后的**生效动作由各业务接口自己做**（如成果审批通过→材料任务补佐证必交项），审批中心只管单子本身
