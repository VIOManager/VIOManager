# 2026-10-16 PM 更新：管理员代建项目 + 节点日期格式修复

> 需求：① 新建项目支持管理员**帮任意成员创建**（代建）；② 比赛节点创建报"参数错误"——datetime-local 出参与后端契约格式不一致。仅改项目管理模块，零表结构变更。

## 一、改了什么

### 1. PR02 代建（后端）

`ProjectCreateDTO` 新增可选字段 `ownerMemberId`，`ProjectServiceImpl.create()` 增加所有人解析分支：

| 场景 | 行为 |
|------|------|
| 不传 / 传自己 | 原行为不变（所有人=当前登录人；无档案 7013） |
| 管理员传他人（**代建**） | 所有人=被帮成员；`ownerName`/OWNER 行的 `memberName/memberOrgId`/`orgId` 默认值**全部跟被代建人**走 |
| 超管代建 | 任意成员 |
| 部门管理员代建 | 仅本子树内成员（越界 7002，与"能看就能管"同口径） |
| 普通用户传他人 | 7002（代建是管理员专属） |
| ownerMemberId 不存在 | 1004（member 表未删除行校验） |

配套改动：

- `ProjectVisibilitySupport.orgManagedBy(orgId, admin)`——组织是否在管理员子树内的公共判定（超管恒真），代建校验复用可见性第 4 条口径，不另起炉灶
- `ProjectServiceImpl.requireMember()`——jdbcTemplate 查 member 表（1004），返回 name/org_id 供 owner 冗余落库
- **契约增量**：PR02 body 增加可选 `ownerMemberId`（对接清单 §1 已同步；接口清单 PR02 行待群里报备修订）

### 2. 节点日期格式修复（前端）

`MilestonePanel.vue` submit()：`<input type="datetime-local">` 取值为 `YYYY-MM-DDTHH:mm`（带 T 无秒），后端 `MilestoneCreateDTO.nodeTime` 契约 `@JsonFormat("yyyy-MM-dd HH:mm:ss")` ——此前直接透传导致 1001 参数错误。现提交前转换：`T`→空格、16 位补 `:00`。

### 3. 前端代建入口（ProjectPage.vue）

新建项目弹窗新增**所有人（管理员代建，选填）**区块，仅管理员角色（SUPER_ADMIN/DEPT_ADMIN）可见：

- 姓名/学号搜索 → A 线 `GET /api/members`（与详情抽屉加成员同款交互）
- 点选成员 → "已选：xxx · 学院"（可重选）；不选=为自己创建
- 提交携带 `ownerMemberId`，成功提示区分"所有人：xxx"与"你是所有人"
- mock 适配器 `POST /api/projects` 同步：代建权限/7002/1004/7013 与真后端同码（顺带把 mock 无档案建项目的 1003 对齐为 7013）

## 四、遗留问题（报备）

1. **A 线成员搜索 NPE（非本次改动引入，建议转 A 线）**：`PersonServiceImpl.page:97` 的 `orgNames.get(person.getOrgId())`——当结果页**全部**成员 org_id 为 NULL 时（如搜"刘"只命中刘慧），`loadOrgNames(空列表)` 返回 `Map.of()`，而 **JDK 21 空 `Map.of()` 实际是 `ImmutableCollections$MapN`，`get(null)` 直接 NPE**（已用最小程序实测证实），接口回 1000。修法一行：`person.getOrgId() == null ? null : orgNames.get(person.getOrgId())`。PM 代建选人、详情抽屉加成员共用该搜索，建议 A 线尽快修
2. 接口清单《项目管理-接口清单.md》PR02 行需同步 ownerMemberId 增量（公共契约文档，群里报备后改）
