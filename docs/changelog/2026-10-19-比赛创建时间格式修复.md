# 2026-10-19 B 线修复：创建比赛报"时间格式有错误"

> 报障：比赛管理 → 创建比赛，填了报名/比赛起止时间保存报错（1001 请求体格式不正确，提示检查时间格式 yyyy-MM-dd HH:mm:ss）。
> ⚠️ 本修复跨到 B 线模块（比赛管理前端），由组长直接指派，开 PR 时一并报备。

## 一、根因

`ContestFormDialog.vue` 的四个起止字段用的是 **date picker（`type="date"`，`value-format="YYYY-MM-DD"`）**，出参只有日期（如 `2026-12-01`）；但这四个字段后端是 `LocalDateTime`——全局契约（规范 §2.1 / PRD §4，`JacksonConfig` 2026-10-14 已按组长拍板对齐后端）要求 **`yyyy-MM-dd HH:mm:ss`**。Jackson 按契约 pattern 反序列化 10 位日期串直接失败 → 1001。

不填时间能创建成功（空串→null），所以此前纯演示没踩到；一旦填日期必炸。

## 二、修复（纯前端，一处文件）

`ContestFormDialog.vue` 四个起止选择器 `date` → **`datetime`**，`value-format="YYYY-MM-DD HH:mm:ss"`（所见即所发，直出契约格式）：

- 选日期时的默认时刻：起始类（报名开始/比赛开始）= 当天 `00:00:00`，截止类（报名截止/比赛结束）= 当天 `23:59:59`（`:default-time`）
- 编辑/池确认预填的回显由 value-format 双向解析，`2026-11-20 08:00:00` 原样进原样出（此前 date picker 对完整时间串的解析也是隐性问题）
- 时间窗顺序校验（报名起 ≤ 报名止 ≤ 比赛起）对 `YYYY-MM-DD HH:mm:ss` 字符串字典序比较仍成立，逻辑不动

后端零改动（契约本就正确）；mock 字符串透传不受影响。

## 三、验证

- curl 复现：`signupStart: "2026-12-01"` → 1001；`"2026-12-01 00:00:00"` → code 0（先排除了 Git Bash 内联中文 GBK 干扰）
- 浏览器（admin）：创建「格式修复验证赛」，报名 2026-11-20 08:00:00 ~ 2026-12-05 23:59:59、比赛 2026-12-10 08:00:00 ~ 2026-12-20 18:00:00 → **创建成功**，列表完整显示四个时间；再开编辑弹窗 → 四个时间**原样回显**
- `vue-tsc` 绿
