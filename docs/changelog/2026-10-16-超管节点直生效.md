# 2026-10-16 PM 变更：超管创建节点直接生效（免审）

> 组长拍板：admin（超管）创建的比赛时间节点**直接成功**——MILESTONE_APPROVE 的审批人本就是超管，"提交→自己批"是走过场。超管从此没有 7014 提审墙；部门管理员仍走 草稿→提审→超管批（审批为"批量生成任务"这一大副作用把关）。

## 一、改动

### 后端

| 位置 | 改动 |
|------|------|
| `MilestoneServiceImpl.create` | SUPER_ADMIN 分支：插入后直接 `status=APPROVED` + `approved_at=NOW()` + `approved_by=超管sys_user.id`，**复用审批回调同一套 `MilestoneSyncSupport.syncOnApproved`** 同步任务（零复制）；同事务，同步失败连创建回滚；学生视图缓存主动失效 |
| `MilestoneServiceImpl.delete` | 修正路径：**PENDING 恒不可删**（审批单挂着 bizId 引用）；DRAFT 可删（原口径）；**超管例外可删 APPROVED/REJECTED**——直生效节点建错了要能删了重建（已同步任务不回收，与 PR24 口径一致） |
| `MilestoneServiceImpl.list` | 管理端列表新增 `approvedBy`（审批人姓名，`sys_user.id`→`real_name` 批量解析防 N+1）；学生视图仍只回 APPROVED 基础字段 |
| `MilestoneVO` | + `approvedBy` 字段（此前接口从不回审批人，前端一直显示"—"） |

部门管理员路径完全不变；`submit` 的 7014 保留（超管代提他人草稿 / 无档案部门管理员场景仍需要）。

### 前端

- `MilestonePanel.vue`：创建成功文案区分角色（超管："已创建并直接生效（超管免审，已同步任务到挂载项目）"）；删除按钮显隐 `DRAFT` 人人可见 + 超管可见 APPROVED/REJECTED（`canDelete`），删除确认区分草稿/已生效话术
- mock 同口径：`applyMilestoneApproved` 抽为共用函数（审批回调与超管直生效零复制），创建/删除规则同步
