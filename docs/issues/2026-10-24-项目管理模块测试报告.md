## 二、发现的问题

### P1：挂载链路断链（已知 bug 复验成立，10-19 已定位，方案待组长确认）

三层根因在当前 main **全部仍在**：

| 层 | 复验证据 |
|----|---------|
| ① UI 建项目无"关联比赛"字段 | 新建弹窗仅有：名称/简介/所有人（代建）/可见性/起止——**无比赛字段**（UI 实测） |
| ② attachable 带 contestId 时硬过滤 | `keyword` 同口径：`attachable?contestId=402` 只返回带 contest_id 的项目；无比赛的 1001/B 全部排除（API 实测） |
| ③ 正常流程建的项目全进死区 | ①+② ⇒ 学生队长挂载下拉**永远只有空池或个别 API 手工建的项目**（UI 实测：下拉仅 1 项） |

修复方案已在组长本地 `.agentdocs/plans/2026-10-19/项目管理-挂载链路修复方案.md`（含 attachable 放宽 contest_id、建项目表单加比赛字段等 7 文件改动），**等待确认后实施**。本次测试用 API 带 contestId 建项目验证了链路后半段完全通畅（挂载/镜像/回溯建任务/解绑/重挂）。

### P2：接口清单文档落后于实现（3 处）

1. **写权限口径**：清单 §2 与错误码表写"仅所有人（7002）"、待确认③标注"按仅所有人从严设计"；实现是 **2026-10-16 拍板的"所有人 or 管理员"**（`ProjectServiceImpl:273` 注释），实测 admin 可改他人项目。**文档需同步拍板结果**。
2. **管理员代建**：PR02 实际支持 `ownerMemberId` 代建（超管任意成员/部门管理员限子树，实测表单有"所有人（管理员代建）"选择器），清单未记。
3. **第三种可见性**：表单有"仅项目内"（PRIVATE）选项，清单 §2 只定义了 PUBLIC/ORG 两条规则。

### P3：UX / 数据缺口（3 项，小）

1. **挂载候选池含已挂载项目**：PR15 无 team 上下文，已挂载的项目仍出现在下拉里，选中点挂载才报 7007（实测复现）。建议前端从池中排除 `list` 中已有 projectId。
2. **解绑后 RELEASED 行仍按挂载中渲染**：PR12 返回 RELEASED 历史行，TeamProjectPanel 不过滤 mountStatus → 解绑后项目仍显示在"挂载项目"区并带解绑按钮（API 实测 + 代码确认）。
3. **部门管理员的节点维护链路在演示数据下不可达**：402 蓝桥杯是校级组织比赛，两协会管理员建节点均 1003（子树范围校验正确）；当前无任何部门组织比赛 → "草稿→提审→超管批"链路无法演示（超管直生效是 10-16 拍板，行为正常）。建议种子补一条协会自己的比赛。
